# Проверка первого прототипа

Дата: 2026-11-18. macOS, Apple Silicon, Python 3.14, Codex CLI 0.169.0, Vosk 0.3.44, sounddevice 0.5.5, модель vosk-model-small-ru-0.22.

## Реальный Codex через подписку

Проверки выполнялись через пользовательскую точку входа `./run`, с отдельными хранилищами и рабочими папками в `/tmp`. Рабочие проекты и прежние диалоги пользователя не изменялись.

| Сценарий | Результат |
| --- | --- |
| `--once`, запрос без инструментов | Получен потоковый `WCHAT_OK`, статус completed |
| Повторный запуск с тем же хранилищем | Возобновлён прежний thread; модель правильно вспомнила `WCHAT_OK` |
| Новая именованная сессия | Создан другой thread, история прежнего диалога не передана |
| Задача создать файл | `result.txt` содержит ровно `WCHAT_ACTION_OK` и перевод строки; содержимое заранее созданного `existing.txt` сохранено |
| Интерактивный `--text`, отмена длительной задачи | `/cancel` привёл к статусу interrupted; он сохранился в истории |
| `/new`, `/use`, `/history`, `/quit` | Переключение и показ сохранённого исхода задачи прошли через настоящий терминальный ввод |
| WAV «Чат, сколько будет два плюс два?» | Локально получено «сколько будет два плюс два», реальный Codex ответил «4.» |

В первых двух текстовых запросах время от отправки turn до первого текста составило около 4,74 и 3,62 с. В проверке WAV - около 3,80 с от отправки уже распознанного текста. Это единичные измерения, не p50/p95; они не включают задержку аудиозахвата, распознавания или холодного запуска. Цель 2,5 с пока не подтверждена.

## Голосовой ввод

- Синтетическое аудио одной фразой: активация и ровно одно поручение.
- Синтетическое аудио с паузой 1,5 с после «чат»: поручение принято после следующей фразы.
- Обычная речь, включая слово «чат» внутри предложения: поручений нет.
- Открытие встроенного микрофона Mac и остановка через `/quit`: прошли. Проверка выполнена с `--transcribe-only`, без отправки микрофонного текста в Codex.
- DJI не был виден в списке устройств. Его захват, переподключение и речь пользователя через него не проверены.

## Автоматические проверки

`make test` проверяет транспорт через отдельный поддельный app-server, последовательность очереди, маршрутизацию в именованные сессии, сохранение истории, запрет повторного запуска с тем же хранилищем, отказ при API-key авторизации, отмену, ошибку модели и падение процесса без скрытого повтора. Отдельные тесты проходят настоящим Vosk по синтетическим WAV.

При проверке выявлена гонка: отмена во время создания сессии не препятствовала отправке поручения. Регрессионный тест сначала завершился ошибкой (completed вместо cancelled), затем прошёл после добавления отложенной отмены. Проверено, что при такой отмене turn не создаётся.

## Остаётся проверить

- Естественная речь, акцент, имена проектов, шум и ложные активации короткого слова «чат».
- DJI, отключение/переподключение устройства, сон и пробуждение, длительная работа.
- Расход батареи и распределение задержек на репрезентативной серии.
- Реальный запрос разрешения Codex и ответы на вопросы агента: обработчики покрыты протокольными проверками, но живого запроса разрешения в этих задачах не возникло.
- Реальные сетевые сбои и исчерпание лимита аккаунта: отказ дочернего процесса проверен автоматическим тестом, это не заменяет реальные условия.

Озвучка, оверлей, автозапуск и автоматическое восстановление соединения ещё не реализованы.


## Окно чата и общий контекст, 2026-11-18

Автоматический набор расширен до 37 проверок.

- Собрано и запущено нативное приложение SwiftUI/AppKit. На этом Mac установленный SDK 27 новее компилятора Swift; сборка использует совместимый SDK через `MacOSX.sdk`. Другой SDK можно передать через `SDKROOT`.
- Через настоящее окно проверены отправка, потоковый ответ, жирный текст и код, создание и переключение диалогов, восстановление истории, завершение процесса и форма разрешения MCP с явным ответом. Форму проверяли на тестовом app-server без доступа к приложениям.
- Ошибка исходного обработчика воспроизведена: `mcpServer/elicitation/request` немедленно отклонялся как неизвестный метод. Регрессионная проверка сначала падала, после исправления запрос ждёт явного ответа. Проверены принятие, отказ и валидация полей.
- При проверке клавиатуры найдено, что SwiftUI TextField отправлял сообщение по Shift+Enter. Поле заменено на NSTextView. Повторно проверено: Shift+Enter сохраняет две строки в поле, Enter отправляет одно поручение.
- Проверены сохранение общего контекста через окно, добавление его к запросу, применение к разным диалогам, обновление/очистка, сохранность после перезапуска и атомарный отказ при неверной рабочей папке. Новый диалог через окно получил ~/Documents/jack.
- С рабочей подпиской Codex и существующим хранилищем отправлено двухстрочное «2 + 2» через окно, получен ответ «4». В окне подтверждено состояние слушающего MacBook Pro Microphone. Старые записи истории сохранены.
- С настоящим Codex отдельно проверены общий маркер контекста и фактический cwd через `pwd`, без чтения и изменения проектных файлов.
- Повторное создание будильника и реальное разрешение Clock не проверялись. DJI, длительная работа, сон и батарея остаются непроверенными. Озвучка, оверлей поверх других окон и автозапуск не реализованы.


## Проверка оформления, 2026-11-18

Нативная сборка прошла. В отдельном экземпляре с тестовым app-server проверены заполненный и пустой диалоги, длинный текст, выделение кода, окно общего контекста, сохранение контекста, переключение диалогов, Shift+Enter и отправка по Enter. Просмотрены окна шириной 1060 и около 800 pt: основные поля и действия доступны, текст переносится. После обновления основного приложения проверены сохранность истории, рабочая папка и запуск микрофона. Новый запрос к облачной модели для этой визуальной правки не выполнялся.


## Зависание при запросе Clock, 2026-11-18

В рабочем процессе зафиксировано зависание окна: основной поток расходовал около 100% одного ядра и повторял расчёты SwiftUI/AttributeGraph. Сервер ожидал запроса доступа Computer Use к Clock. Исходная задача остановлена с неизвестным результатом, без повторного запуска.

Нативная регрессионная проверка до исправления падала: изменения состояния микрофона вызывали прокрутку переписки. Точные условия первоначального зависания не удалось надёжно воспроизвести на записи запроса; отдельно воспроизводилась лишняя инвалидация прокрутки.

Исправления: прокрутка только при изменении сообщений или выбранного диалога, объединение потоковых обновлений после завершения текущей транзакции, отображение последних 100 сообщений в обычном VStack с кнопкой загрузки предыдущих, независимая область разрешений, управление размерами окна со стороны AppKit.

Проверки: 38 Python-тестов; `make test-native` проверяет отсутствие прокрутки от 200 событий микрофона и 100 одинаковых снимков разрешений, сохранность карточки и обновление потокового ответа. В настоящем окне с подпиской Codex получен реальный запрос Clock, раскрыты и свёрнуты подробности, отправлен отказ, получен завершённый ответ. Во время ожидания окно отвечало; после завершения процесс вернулся к 0% CPU. Создание будильника и предоставление реального доступа Clock в этой проверке не выполнялись.
