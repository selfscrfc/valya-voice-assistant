# План реализации

Уточнён 2026-11-18: основной сценарий с первого прототипа - постоянно включённый микрофон, слово «чат», затем поручение. Push-to-talk является необязательным запасным способом ввода, а не первым этапом продукта.

Текущий результат: терминальный исполнитель, непрерывный локальный распознаватель и отдельное окно чата macOS реализованы. Общий контекст проектов сохраняется локально и добавляется во все диалоги; папка новых диалогов по умолчанию ~/Documents/jack. Проверен полный путь синтетического аудио до реального ответа Codex, продолжение сессий, файловое действие и отмена. DJI и эксплуатационные метрики ещё не проверены. Подробности: [проверка прототипа](validation.md).

## Сессии

- По умолчанию используется один постоянный диалог `default`. Перезапуск клиента сохраняет его связь с thread Codex.
- Для другой темы или проекта пользователь явно создаёт именованный диалог с рабочей папкой либо переключается в существующий. Автоматическое угадывание адресата не требуется.
- Голосовой ввод фиксирует адресата при активации словом «чат», письменный - при отправке. Переключение диалога не перенаправляет уже принятые поручения.
- Первый прототип исполняет одну задачу за раз; остальные находятся в видимой очереди. Микрофон продолжает слушать во время выполнения. Параллельное исполнение между проектами можно добавить после проверки конфликтов инструментов.
- После аварии незавершённые задачи требуют проверки. Автоматического повторного выполнения действий нет.
- Первоначально клиент управляет только собственными сессиями. Подключение к сессии, одновременно открытой в другом клиенте, откладывается.

## Интерфейс

Работают два клиента к одному исполнителю: терминальный `./run` и нативное окно `./desktop`. В окне переписка отделена от диагностики, есть потоковые ответы, оформление текста, история, создание и выбор диалогов, очередь, отмена, карточки разрешений и редактор общего контекста. Одновременно подключаться к одному хранилищу нельзя.

Приложение `~/Applications/Valya.app` запускается без терминала. Закрытие окна скрывает чат, а процесс Codex и микрофон продолжают работать. Строка меню позволяет открыть чат и полностью завершить ассистента. Озвучка по «звук» реализована. Оверлей и автозапуск остаются отдельными этапами.

## Порядок работ

1. **Терминальный исполнитель.** Постоянный app-server, проверка входа ChatGPT, потоковый ответ, именованные диалоги, история SQLite, очередь, отмена и запросы разрешений. Проверить реальный запрос, продолжение диалога после перезапуска и изоляцию нового диалога.
2. **Непрерывный локальный голосовой ввод.** Микрофон -> Vosk -> детектор слова «чат» -> сбор поручения до паузы -> та же очередь. Распознавание работает непрерывно, кнопка не требуется. Первый цикл использовал одну небольшую русскую модель. С 2026-11-19 поручения после активации распознаёт Whisper large-v3-turbo через MLX; двухсекундный буфер сохраняет начало фразы.
3. **Проверка полного цикла.** Аудиофикстуры с кодовым словом, без него, с паузой и несколькими поручениями; реальный DJI, сохранность истории, изменение активного диалога, обрыв процесса и отмена. Синтетическое аудио не заменяет проверку голоса пользователя и фоновых шумов.
4. **Качество и энергия.** Настройка пауз и детектора, сравнение Vosk/Whisper, измерения задержки, батареи и ложных активаций.
5. **Дополнительные интерфейсы.** Оверлей, автозапуск, опциональный push-to-talk; затем телефон и удалённый исполнитель.

Для быстрого проверяемого прототипа ядро и CLI реализуются на Python, локальный аудиоввод - через PortAudio. Нативный интерфейс позже может подключаться к тому же ядру. Это уточнение первоначального предложения о полностью Swift-прототипе. Контракты Codex проверяются по схеме установленного CLI, а не по предположению о совместимости версий.

## Критерий завершения первого прототипа

Пользователь запускает клиент, произносит «Чат, ...», получает ответ через подписку Codex и продолжает тот же диалог. Обычная речь не запускает задачи. Новая именованная сессия не получает историю другой. Остановка/ошибка не стирают прежние сообщения и не вызывают скрытого повтора задачи. В отчёте отдельно отмечаются проверки на синтетическом аудио, живом микрофоне и реальном Codex.
